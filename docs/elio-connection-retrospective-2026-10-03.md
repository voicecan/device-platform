实体设备 CAPSO-92E9，硬件 B100、固件 v0.6.5，通过已固定的 device-core 0.1.0-preview.19 与当前 Elio 服务完成连接。

- 18:25：蓝牙认证和状态读取成功。Home2 配网返回 WIFI_CONFIGURATION_REJECTED；随后重新读取，Wi-Fi 状态和模式均为 0，电量 10%，设备报告 low，服务器未收到连接。
- 20:01：充电后重新建立浏览器蓝牙连接，读取电量 100%、normal，Wi-Fi 仍未连接。
- 20:03:13：重新提交同一 Home2 网络，使用原有凭据与 WPA2 配网选项。

- 20:03:40：服务器确认设备上线，页面自动进入详情；设备录音开始同步。

此次成功复测没有改变路由器设置、设备固件或配网库，也没有重置或解绑设备。Home2 是 2.4 GHz WPA/WPA2 Personal 混合网络；本次成功证明此组合在该设备与运行库上可用，不代表所有混合模式或 5 GHz 网络均兼容。

## 能确认与不能确认的原因

蓝牙连接仅证明近场通信和认证成功，不能证明 Wi-Fi 或服务器在线。此前配网确实未完成，不只是在线徽标显示错误。

低电量是合理线索：失败时 10% / low，成功时 100% / normal。但充电、时间间隔与蓝牙重连同时发生，没有单变量对照，不能断言低电量就是根因。设备与配网库只给出拒绝结果，没有拒绝原因；也不能据此指认密码错误、混合加密错误或软件缺陷。

另外，优化后的浏览器检查实际复现了一个状态显示缺陷：详情轮询已经读到在线，设备选择器仍使用旧列表显示离线。该缺陷由当前设备在候选列表中存在时未替换其旧快照造成；已让选择器使用详情的最新快照并加入回归测试。这与此前 Wi-Fi 未连上的实际失败不同。

确定的程序体验问题是：准备状态显示不足、失败诊断缺少现场观察、连接后仍强调重新配置。后续优化针对这些已经证实的问题。

## 程序改进

1. 首次连接保留两步：蓝牙、Wi-Fi。凭据备份与服务器设置自动处理；仅服务器确认上线后进入详情。
2. 配网拒绝后自动刷新真实设备状态；若已有有效网络，提供明确的“使用当前 Wi-Fi 并完成”，不默认为新设置已接受。
3. 配网页显示本次蓝牙读取的电量、状态与时间。低电量提示仅建议接通电源，不阻止用户继续，也不把它标为失败原因；断开或切换设备即清除实时提示。
4. 诊断导出增加读取时间、电量和 Wi-Fi 观察，保留最近 24 条。只选取允许的字段，不包含 SSID、密码、令牌、音频或原始设备帧；仅存在当前页面会话中。
5. 成功后收起诊断时间线和重新配网表单，保留高级入口与原有维护能力。已在线时无需额外连接蓝牙；修改网络仍需明确连接蓝牙并操作。

检查期间看到服务器上线与离线交替事件；57 条录音已全部同步、失败 0 条。当前未取得 WebSocket 关闭原因，不能把此次配网成功视为长期连接稳定性已经验证。

## 验证边界

20:03 的实体设备上线证据对应此次 UI 优化前已经成功的连接流程。新的观察提示与折叠布局通过回归测试和浏览器检查；示例失败状态截图不代表重新制造了实机故障。当前根因仍待固件或运行库提供更详细拒绝原因后验证。
