# AI tool connection flow

The platform owns devices, recording sync/storage and authorization. Transcription and agent workflows belong to the user's chosen tool. Demo apps are optional.

Local setup supports OpenClaw, Codex, Claude Desktop and generic stdio clients. OpenClaw configuration uses `mcp.servers` with `command`, `args`, and `enabled`. It does not set `transport: "stdio"`, matching `openclaw mcp add`. Generated commands are `openclaw mcp add` and `openclaw mcp doctor <name> --probe`. Current official references: https://docs.openclaw.ai/tools/mcp and https://docs.openclaw.ai/cli/mcp/registry (checked 2026-10-20). Stop the OpenClaw Gateway before `add`, `login`, `probe`, or `doctor --probe`; those commands take an exclusive config lock. No OpenClaw installation is bundled or automatically modified.

Quick setup runs on the Platform computer only. The runner reads an owner-only token reference and is restricted to loopback callers. Remote OpenClaw and Codex use the public HTTPS `/mcp` URL with Streamable HTTP and OAuth. OpenClaw remote setup is `openclaw mcp add --url <mcp> --transport streamable-http --auth oauth --oauth-scope "<scopes>"`, then `openclaw mcp login <name>`. Codex remote setup is a `[mcp_servers.<name>]` table with `url` and explicit `scopes`, then `codex mcp login <name> --scopes <comma-separated>`. Do not use `codex mcp add --url` for this server: current Codex starts OAuth immediately and requests every advertised scope. Do not also set `oauth_resource` to the same MCP URL; current Codex already sends `resource` and a duplicate parameter is rejected by strict providers. Local stdio paths and credential files cannot be copied to a cloud Gateway. Consent selects an Application that already has the `mcp_remote` channel and every requested scope.

Metadata permission is the default. Recording content is a separate opt-in profile requiring `consent: true`; it adds temporary download link creation and revocation, never device controls/deletion. Existing metadata credentials are not widened. Same group/profile reuses a credential across client formats; revoking it affects every client using that credential. The content profile uses a distinct MCP server name to avoid overwriting existing Codex setup. Revoked/expired connections require explicit management.

Generated configuration is not client verification. Codex automatic installation checks the runner/tool catalog and saved config, not audio processing. OpenClaw verification happens in that user's running installation. Audio access grants allow retrieval of original audio, which may require a codec and transcription service configured by the user. No ASR or LLM dependency is added to Platform.

Main UI: overview -> add device dialog -> recordings -> AI tools. Recording date means server ingestion date, not an inferred capture timestamp. Original download remains the existing authenticated streaming Admin route; app/MCP consumers use temporary grants. Technical metadata and device maintenance remain available under disclosures.
