# Security model

The public API assumes the V1.2 line protocol can eventually be reverse engineered. Authorization rests on deployment isolation, random per-device credentials, TLS, local identity, current device-group ownership, scoped application tokens, immutable storage, and audit records—not obfuscation.

Device credential plaintext exists only while provisioning or authenticating a connection. At rest the database contains an HMAC verifier and AES-256-GCM ciphertext bound to the device and credential record. The deployment master key and token pepper are separate owner-only files and must be backed up with the database; losing them loses device control.

Human sessions use Secure cookies when the public base URL is HTTPS, SameSite Strict, HttpOnly, and CSRF validation for mutations. Passwords use Node's Argon2id implementation with versioned encoded parameters. Login errors do not distinguish a missing user from a wrong password and use one precomputed dummy hash for missing users. Exponential normalized-identity/IP blocks plus a five-minute IP-wide failure window survive restarts and prevent username rotation from multiplying Argon2 work. The offline password command revokes sessions and clears that identity's lock records without accepting the password on the command line.

Group access is fail-closed. Recording rows do not carry an authorization group snapshot. Every metadata/content/event query joins the recording/event to its Device and checks the Device's current `group_id`; guessing an out-of-scope ID returns 404.

Webhook endpoints default to HTTPS and reject loopback, link-local, documentation, metadata, reserved, multicast, and private IPv4/IPv6 addresses. Delivery pins the validated address while retaining the original Host/TLS server name, closing the DNS-rebinding gap. `VOICECAN_DEPLOYMENT_PROFILE=intranet` is the explicit trusted-network exception and permits private HTTP callbacks; production refuses the corresponding insecure overrides. The dispatcher rechecks device ownership and event ownership epoch before delivery. Schema v5 adds a 30-second CAS delivery lease (`claimed_by`, `claim_expires_at`); completion requires the same claimant and pending state, while endpoint disable, Device release/transfer, and replay clear the claim. Rotation stages a next secret and secret ID before activation; replay and backfill use an explicit audit trail and replay namespace.

Provisioning grants are short-lived, one-time, atomically consumed, and bound to an exact browser Origin. The frozen firmware still cannot provide cryptographic proof that the nearby unclaimed device is physically intended by the administrator.

Cross-deployment transfer-out is source-admin initiated, single-device, exact-Origin, and expires after five minutes. The source Server never returns the old credential as plaintext: the self-hosted browser generates an ephemeral RSA-OAEP-2048/SHA-256 key pair and receives only ciphertext sealed to that public key. The browser verifies the selected serial, authenticates over BLE with the decrypted old credential, and sends the reviewed non-erasing unbind semantic command. The source claim and credential are revoked only after a successful device ACK and a final ownership/credential CAS. Timeout, disconnect, mismatch, replay, active upload, or stale state leaves the source claim intact. The plaintext exists briefly in browser and Server memory and is overwritten on a best-effort basis; compromised browser/host memory remains an accepted frozen-firmware risk.

The deployment keyring retains old versions during batch rewrap and restore drills. Backups contain the SQLite snapshot, immutable objects, keyring, token pepper, and a version manifest. Restore refuses a non-empty target and verifies database integrity plus completed setup; restoring never reopens first-admin setup.

Known frozen-firmware limits remain accepted risks: near-field claim races, BLE capture where link encryption is absent, replay where the protocol has no nonce/counter, and impersonation after raw Device Token extraction. This preview makes no claim to resist those attacks.
